# congestion-aci Specification

## Purpose

혼잡도 에이전트가 저장된 perception 세션 관측값을 읽기 전용으로, 짧고 일정한 형식의 텍스트로 조회하게 해 주는 에이전트-컴퓨터 인터페이스를 정의한다.

## Requirements

### Requirement: 세션 폴더 적재
시스템은 `session.json`과 `results.jsonl`이 들어 있는 세션 폴더 하나를 입력으로 받아야 한다(SHALL). 두 파일 중 하나라도 없거나 JSONL 행을 해석할 수 없으면 에이전트를 시작하기 전에 원인 파일과 행 번호를 담은 오류로 멈춰야 한다(MUST).

#### Scenario: 정상 세션 적재
- **WHEN** 사용자가 `session.json`과 400행짜리 `results.jsonl`이 있는 폴더를 지정한다
- **THEN** 시스템은 세그먼트 400개를 0부터 399까지 번호를 매겨 적재한다

#### Scenario: 깨진 행
- **WHEN** `results.jsonl`의 12번째 행이 올바른 JSON이 아니다
- **THEN** 시스템은 LLM을 호출하지 않고 `results.jsonl` 12행을 가리키는 오류로 종료한다

### Requirement: 판정 입력에서 기존 LLM 출력과 원시 트랙 제외
도구 출력은 세션에 기록된 기존 LLM 판정(`agent` 필드)과 원시 트랙(`tracks`), 처리 시간(`cv_elapsed_sec`)을 어떤 형태로도 포함해서는 안 된다(MUST). 에이전트는 perception 관측값, 집계값, 트리거 정보만 본다.

#### Scenario: 기존 판정이 있는 세그먼트 조회
- **WHEN** 에이전트가 기존 `agent.assessment`가 `anomaly`인 세그먼트를 조회한다
- **THEN** 도구 출력에는 `assessment`, `action`, `reasoning`, `tracks` 값이 나타나지 않는다

### Requirement: 세션 개요 도구
시스템은 세그먼트 수, 세그먼트 길이(초), 전체 시간 범위, 트리거 종류별 세그먼트 수, 혼잡 등급(`level`)별 세그먼트 수를 돌려주는 개요 도구를 제공해야 한다(SHALL).

#### Scenario: 개요 조회
- **WHEN** 에이전트가 101개 세그먼트에 트리거가 있는 세션의 개요를 요청한다
- **THEN** 출력은 전체 세그먼트 수와 트리거 종류별 개수를 보여 주고, 그 개수의 합은 101이다

### Requirement: 구간 보기 도구
시스템은 시작·끝 세그먼트 번호를 받아 그 범위의 세그먼트를 한 행에 하나씩 표로 보여 주는 도구를 제공해야 한다(SHALL). 한 번에 최대 20행만 보여 주고, 잘린 경우 남은 범위를 알려야 한다(MUST). 실수 값은 소수 둘째 자리까지 반올림한다.

#### Scenario: 범위가 20행을 넘음
- **WHEN** 에이전트가 세그먼트 0부터 49까지 보기를 요청한다
- **THEN** 출력은 0부터 19까지 20행을 보여 주고, 20부터 49가 남았다는 안내를 덧붙인다

#### Scenario: 범위 밖 번호
- **WHEN** 에이전트가 400개 세그먼트 세션에서 세그먼트 450을 요청한다
- **THEN** 도구는 유효 범위 0–399를 알려 주는 오류 관측을 돌려주고 루프는 계속된다

### Requirement: 세그먼트 검색 도구
시스템은 트리거 종류, 혼잡 등급, 최소 인원 조건으로 세그먼트를 찾아 번호 목록과 일치 개수를 돌려주는 도구를 제공해야 한다(SHALL). 번호 목록은 최대 50개까지만 보이고 전체 일치 개수는 항상 표시해야 한다(MUST).

#### Scenario: 트리거로 검색
- **WHEN** 에이전트가 트리거 `stagnation`인 세그먼트를 찾는다
- **THEN** 출력은 일치 개수와 해당 세그먼트 번호를 오름차순으로 보여 준다

#### Scenario: 일치 없음
- **WHEN** 어떤 세그먼트도 조건을 만족하지 않는다
- **THEN** 출력은 "일치 0개"를 명시하고 오류로 처리하지 않는다

### Requirement: 구역 추이 도구
시스템은 구역 이름과 세그먼트 범위를 받아 그 구역의 인원 최솟값·최댓값·평균과 최댓값이 나온 세그먼트 번호를 돌려주는 도구를 제공해야 한다(SHALL). 없는 구역 이름이면 사용 가능한 구역 목록을 담은 오류 관측을 돌려준다(MUST).

#### Scenario: 없는 구역
- **WHEN** 구역이 A, B, C뿐인 세션에서 에이전트가 구역 `D`를 요청한다
- **THEN** 도구는 사용 가능한 구역 A, B, C를 알려 주는 오류 관측을 돌려준다

### Requirement: 도구는 판단을 생산하지 않음
조회 도구의 출력은 관측값과 그 단순 집계(개수, 최솟값, 최댓값, 평균)만 담아야 하며 혼잡 판정이나 대응 권고를 담아서는 안 된다(MUST). 판정은 에이전트의 최종 제출로만 만들어진다.

#### Scenario: 높은 인원 구간 조회
- **WHEN** 에이전트가 `level=high` 세그먼트를 조회한다
- **THEN** 출력에는 `normal`/`caution`/`anomaly`나 `monitor`/`alert` 같은 판정 값이 없다
