# 공통 설계 결정

[상위 계약](contract.md)을 따른다. capability별 외부 동작은 명세에 두고, 여기에는 여러 capability에 걸친 결정과 이유를 둔다.

## 실행 루프는 SDK에 맡긴다

OpenHands SDK가 루프, LLM 재시도, 반복 감지, 이벤트 저장을 맡는다. 우리 코드는 Agent·LLM 구성, 최종 상태 판정, 실행 요약 기록에 집중해 SDK의 실행 흐름을 중복 구현하지 않는다.

## 세션 적재 때 허용 필드만 남긴다

`environment/session.py`에서 관측값만 `Segment`로 옮기고, 조회와 제출이 같은 `Session`을 사용한다. 기존 판정·트리거를 도구마다 지우는 대신 처음부터 접근 경로를 없앤다.

이 차단은 필드 선택 방식이다. 세션 식별자·구역명·오류에 인용되는 입력 문자열을 정화하는 별도 필터는 없다. 조회 비노출 테스트는 차단용 합성 세션의 출력과 도구 설명을 검사한다.

## 도구 정의와 실행 로직을 나눈다

도구별 폴더에 `definition.py`와 `impl.py`를 둔다. 조회 도구는 순수 조회 함수와 공용 `QueryTool`·`QueryExecutor`로 연결해 스키마와 SDK 관측 변환의 중복을 줄인다. 상태를 저장하는 `submit_judgment`는 자체 Executor를 사용한다.

## 출력 형식은 한 곳에서 관리한다

`tools/utils/format.py`가 수치 표시, 표, 표의 남은 범위, 번호 목록 제한을 맡는다. 여러 조회에서 같은 관측값을 같은 형식으로 읽게 한다. 검색 조건을 되보여 주는 문자열은 원래 인자 표현을 사용한다.

## 입력 오류는 관측으로 돌려준다

Executor는 `ToolError`를 `is_error=True` 관측으로 바꾼다. 에이전트가 허용 값과 범위를 읽고 인자를 고쳐 다음 호출을 할 수 있게 한다. 모든 예외를 입력 오류로 취급하지는 않는다.

## 제출과 종료를 분리한다

`submit_judgment`는 검증한 판정을 `JudgmentStore`에 저장하고 `finish` 호출을 안내한다. SDK는 `finish` 호출로 종료하므로 제출 도구를 `finish`로 만들면 검증 실패까지 종료로 이어진다.

## 판정의 인원 수는 세션에서 채운다

제출 Action은 추가 인자를 허용하고, 검증기가 정해진 인원 필드를 제거한 뒤 `evidence_totals`를 관측값으로 채운다. LLM이 제출한 구조화된 인원 수를 신뢰하지 않기 위한 결정이다. 자유 텍스트의 숫자나 임의의 추가 필드까지 제거하는 방식은 아니다.

## 전역 도구 등록을 실행마다 갱신한다

`register_tool`은 프로세스 전역 등록이다. 실행마다 현재 세션과 저장소를 쥔 도구를 같은 이름으로 다시 등록해 이전 세션을 대체한다. 이 구조를 동시 실행의 세션 격리 보장으로 해석하지 않는다.

## 실행 기록은 SDK 이벤트와 요약으로 나눈다

기본 `trajectories/<시각>/` 아래 `conversation/`에는 SDK 이벤트를, `run.json`에는 질문·설정·결과·토큰 집계를 남긴다. `delete_on_close=False`로 대화 종료 뒤에도 기록을 보존하고 `visualizer=None`으로 SDK의 터미널 표시를 끈다. CLI의 `--output-dir`로 상위 출력 폴더를 바꿀 수 있다.

## SDK 버전은 고정한다

`pyproject.toml`에서 `openhands-sdk==1.56.0`을 고정한다. 도구 등록, 지연 초기화, 종료 상태와 이벤트 형식에 의존하므로 버전을 올릴 때 해당 동작을 다시 확인해야 한다.
